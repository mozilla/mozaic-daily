# tests/ — test suite

Unit and integration tests for `mozaic_daily`. Mirrors the package structure: one test file per source module.

## Files

| File | Tests |
|---|---|
| `test_ingest.py` | The adjustment ingest step: CSV/Excel reading with thousands separators, column guessing (incl. a 28d-MA twin by name and by smoothness), type-label normalisation, the contract checks that halt (weekly rows, start after seam, end before year end, actuals after forecast) and warn (moving-average-like, cumulative, mixed sign), horizon construction (zero before / verbatim / held flat at the final 28d mean, sign flip, gap interpolation, `actuals_through` in place of a type column), plan validation, registry collisions and comment-preserving append, idempotent `.gitignore` exceptions, and end-to-end builds that resolve through the real `resolve_overlays` / render through `render_adjustment`, plus the `--replace` REVERT stash |
| `test_overlays.py` | Registry-driven overlay dispatch (`overlays.py`): `applier` selection and the raise on a missing/unknown applier, the exact-date spec gate (null never matches, two claimants raise), disabled codes skipped, data-source and allocation-key validation, trailing-share exclusions and fixed-share dispatch, two overlays stacking with distinct sentinels and round-tripping at the world row, and — against the committed repo — that the 2026-08-02 seam still resolves to exactly `l` + `o` |
| `test_adjustments.py` | Filename markers, sidecar meta round-trip, composite adjustment math (`linear_ramp`, `step`, `daily_series`, `daily_file` incl. the 28d smoothing and hold-past-end), `load_adjustments_from_dir(require_specs=)`, and the per-tile bidirectional appliers used by `l` / `o` (spec validation, country shares — both trailing-DAU (with `exclude_countries`) and fixed-from-spec, subtract from training, add-back to forecast, per-overlay sentinels so two overlays stack) |
| `test_validation.py` | All validation rules: schema, string formats, row counts, nulls, duplicates |
| `test_forecasting.py` | `get_forecast_dfs`, `get_desktop_forecast_dfs`, `get_mobile_forecast_dfs` |
| `test_config.py` | `get_runtime_config`, date logic, `DateConstraints` |
| `test_queries.py` | `QuerySpec.build_query()` SQL generation |
| `test_data_fetching.py` | Data fetching helpers, checkpoint read/write, `query_to_dataframe` heartbeat watchdog (format, hint-on-first-tick, `Next ≤Ns` liveness bound) |
| `test_table_manipulation.py` | `format_output_table`, ALL-row generation, column renaming |
| `test_seam_ma.py` | `src/mozaic_daily/seam_ma.py` — the variance-matched actuals→forecast seam MA. Smoothness, far-horizon (Dec-15) byte-identity, anti-tautology guard that the naive blend wobbles, **weekday-invariance of the trend estimator**, the **identity invariant** (all-actuals input ⇒ the transition is a no-op), edge unbiasedness, and a **canary** asserting the suite still rejects the known-bad estimator. Replaces the archived `test_export_canonical_curves.py`. See `research/ma-seam-turbulence/` § Fix A |
| `test_ladder.py` | `ladder.py`: overlay fingerprint changes with the curve file not just the spec; the rung key ignores fingerprints of disabled overlays (the caching property), changes with an enabled overlay's edit, the config and the seam, and is order-independent; impact ordering with tiebreak; cumulative subsets grow only on overlay codes so display-layer codes share a run; ladder rows accumulate display effects and steps; cumulative curves apply display-layer pieces only from the seam |
| `test_run_flow.py` | `run_flow.py` CLI argument parsing and backfill state logic |
| `test_smoke.py` | **End-to-end pipeline tests** (marked `smoke`), not an import check: runs `main()` with BigQuery and mozaic mocked and asserts the pipeline completes, calls `populate_tiles` / `curate_mozaics` in order and once per data source, honours the checkpoint system, and processes desktop and mobile separately |
| `test_organic.py` | **The mobile paid/organic split `p`, both halves.** `organic_source` (producer): the pure transforms building the measured split, plus the four checks that must raise — partition identity, tail overlap, split coverage, shredder drift. `organic` (consumer): `split_training_to_organic` (pre-mozaic), `marketing_paid_level` (lift + anchor, held flat past the curve's end), `add_paid_to_forecast` (post-mozaic), `paid_seam_step`. The fixture deliberately ramps the organic share over time and varies it sharply by country, because both are true of the real data (1.10% paid in 2024-06 → 11.58% by 2026-07; 0.2% in RU vs 27.6% in ID) and both are what a naive implementation gets wrong |
| `test_model_config_knobs.py` | The mozaic `ModelConfig` knobs this repo drives, focused on `seasonality_corr_threshold` — the per-tile cutoff on desktop's level/volatility correlation that decides the additive/multiplicative regime |
| `test_iran_fill.py` | The fill **producer** (`scripts/generate_iran_fill.py`): unit tests on the pure transforms (population↔segment mapping, day-of-week profile, re-seasonalization) plus artifact-level checks |
| `test_iran_fill_integration.py` | The mozaic-daily **wiring**: that `data_source` is forwarded from the platform wrappers into `mozaic.populate_tiles`, so the package selects the matching built-in fill |
| `test_mozillaonline_model.py` | **Contract** tests on the active MozillaOnline migration *artifact* — the output contract the `o` applier depends on — run against whatever `mozillaonline.json` currently points at |
| `test_seam_bridge.py` | `scripts/seam_bridge.py` — the seam kink diagnostic (`kink_score`) and the daily-level bridge that corrects an actuals→forecast **level** mismatch by decaying an offset over the first window |
| `test_score_near_horizon.py` | `scripts/score_near_horizon.py` — near-horizon scorer, incl. that its MA is the canonical `display_ma` and that its headwind ramp clamps at the anchor date |
| `test_verify_training_rows_are_actuals.py` | `scripts/verify_training_rows_are_actuals.py` — the check that licenses substituting parquet `training` rows for a ~$5 BQ actuals query. Concentrates on the **failure** branches (1-DAU perturbation, overlay-style contamination, missing probe date, and an **empty probe that must not pass vacuously**), since a version that always passes would authorise using modified training data as actuals |
| `test_mobile_app_breakdown.py` | `scripts/mobile_app_breakdown.py` — the per-app mobile DAU split. Unit-tests the transforms on synthetic frames with hand-computed shares, and asserts the loud failures that matter: a row matching **two** app patterns (double-counted) or **none** (silently dropped), which is how a change to the upstream `app_name` vocabulary would first show up. Plus a guarded check that the on-disk August build still splits four ways |
| `test_mobile_scoring.py` | `scripts/mobile_scoring.py` — the August mobile scan scorer. Targets the four regressions that would silently mis-score the whole search: reading `desktop_dau` instead of `mobile_dau` (a ~45× error), copying desktop's `'{"os": "ALL"}'` segment selector (matches zero mobile rows), computing the seam step from the forecast MA on both sides (hides the handoff), and an unclamped ramp past the Dec-15 anchor. Plus a guarded lock that the scorer reproduces the published 17,601,155 — the check that licenses comparing probes against it |
| `test_export_desktop_no_headwind_csv.py` | `scripts/export_desktop_no_headwind_csv.py` — the desktop-only, `h`-removed counterfactual export. Because the output looks like the canonical forecast, the tests target what would ship a wrong or mislabelled number: a ramp reconstructed with different semantics than the notebook that produced the published file (must be **zero at `start_date`** and **unclamped past the anchor**), a ramp leaking before the seam (would rewrite actuals), the guards that raise when a **second spec moves desktop** / an unsupported spec `type` / an empty dir / a missing `headwind.json`, and that the summary's `win10_headwind_added_back_*` ledger columns actually recover the published figures. Round-trips a flat synthetic curve so the expected stripped value is a literal, not a recomputation of the code under test. Its overshoot test is what caught the stale `156/135` figure in `data-official/2026-08/adjustments/_index.md` |
| `test_export_desktop_ex_ir_cn_csv.py` | `scripts/export_desktop_ex_ir_cn_csv.py` — the desktop-only ex-Iran/ex-China export. Locks the two claims a refactor would silently break: that `ALL` reconciles to its country tiles (tolerance must **accept ~1e-8 float noise and reject 0.5 DAU**, since a 0.5 residual could move a published figure), and that the MA is taken on the **differenced daily series** — `test_ma_of_difference_is_not_difference_of_mas` fails on a "simplification" to subtracting per-country MAs, while its sibling proves the two agree from seam+27 onward so no headline is at stake. Also: raises when IR or CN has no tile (they would hide inside ROW), the canonical scope sits **below** the no-headwind one (a sign flip would publish the headwind as a tailwind), and the ledger signs are inverted between the pair. Guarded real-build class asserts the **world reconstruction reproduces the published CSV**, that IR's training rows carry the **real shutdown crater and not the counterfactual fill** (which is what licenses using training rows as actuals), and that IR+CN are a material 4–8% of desktop |
| `__init__.py` | Marks the package so `pytest` import mode resolves sibling modules |
| `conftest.py` | Shared fixtures (sample DataFrames, runtime config stubs) |

**Not collected by the live suite:** `_archive/tests/` is in `norecursedirs` (`pyproject.toml`). Those two
modules exercise the frozen 2026-06 seam MA, which cannot change, so reporting on them would be noise.
Run them explicitly with `pytest _archive/tests/ -q` to confirm frozen behaviour still holds.

## Where new tests go

- **New module**: add `test_<module_name>.py` here
- **New validation rule**: add to `test_validation.py` in the appropriate section
- **Shared fixtures**: add to `conftest.py` if used by more than one test file
- **Integration tests that hit BigQuery**: mark with `@pytest.mark.integration` and gate on CI credentials

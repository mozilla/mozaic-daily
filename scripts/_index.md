# scripts/ — operational and development helper scripts

One-off runners, backfill tools, and utilities for local development. Not part of the `mozaic_daily` package.

## Scripts

| Script | What it does |
|---|---|
| `run_main.py` | Run the full forecasting pipeline locally with checkpoints (bypasses Metaflow). `--disable-adjustment CODE` (repeatable) forces any registered adjustment off; the `--no-*` flags are aliases for `m`/`l`/`o`/`p` |
| `run_flow.py` | Unified Metaflow runner: `local`, `remote`, `deploy`, `backfill` |
| `run_validation.py` | Validate a checkpointed forecast parquet file |
| `check_logs.py` | Parse backfill logs to find successes, failures, and ambiguous runs |
| `export_forecast_csv.py` | Export a forecast parquet checkpoint to CSV |
| `generate_iran_synthetic.py` | Run Mozaic for Iran alone and save ALL-level totals (historical + forecast) |
| `add_iran_to_forecast.py` | Add synthetic Iran DAU values to a no-Iran forecast via summation |
| `run_comparison_forecasts.py` | Run multiple forecast variants for side-by-side comparison |
| `test_local_docker.sh` | Build and smoke-test the Docker image locally |
| `generate_iran_fill.py` | Produces the Iran counterfactual-fill artifact for the shutdown gap (current approach; supersedes the synthetic pair above) |
| `build_fenix_organic_split.py` | Producer for the `p` adjustment: builds a cycle's measured Fenix paid/organic split from the growth-source mirror + a tail extension, into `data-official/{YYYY-MM}/organic/`. Four checks raise on failure. **Always pass `--production-raw`.** ~141 GB scan, ~$0.70; run once per cycle |
| `verify_forecast_states.py` | Audit on-disk forecast artifacts, verify raw/adjusted state, write `tmp/inventory.csv` |
| `migrate_forecast_names.py` | Rename artifacts to the `.raw.` / `.adj-{codes}.` convention and write sidecar metas |
| `regenerate_composites.py` | Reproduce composite CSVs from raw parquets via `mozaic_daily.adjustments`; diffs against on-disk |
| `plot_forecast_set.py` | Generate the canonical plot set (`global_<platform>.png` etc.) from a forecast checkpoint, mirroring the prior cycle's `csv/plots` |
| `ingest_adjustment.py` | **Ingest a delivered headwind/tailwind file.** `inspect FILE --forecast-start` guesses the date / value / actuals-forecast columns with evidence, checks the `templates/tailwind/` contract and exits 2 on any error (weekly rows always halt; start after the seam or end before Dec 31 of the forecast year halt). `build FILE --name --code --family {per_tile_overlay,display_layer} --platform --forecast-start --cycle --date-column --value-column [--type-column|--actuals-through] [--sign -1] [--allocation] [--shares] [--exclude]` writes `data-official/{cycle}/{name}/` (source copy, horizon parquet held flat at the final 28d mean to Dec 31 next year, csv twin, meta, spec, a shape plot in `plots/`, `_index.md` skeleton) plus the registry entry and `.gitignore` exception; `--values-are-28d-ma` uses an already-smoothed file as-is; `--rebase-to-seam` shifts a curve anchored at an earlier seam to 0 at this seam (delivered series kept, offset in meta); a title line above the header is skipped; updates to a registered code follow its `spec_glob` layout. `--withheld` (per-tile only) writes `"withheld": true` into the spec so the code is registered and gated but skipped by the run until the key is removed; `--replace` stashes the live build in a `*_REVERT_{date}/` dir; `plot` re-renders the shape plot for an adjustment already on disk. Never runs the model. Logic in `mozaic_daily.ingest_inspect` / `ingest_build`; driven by `/ingest-adjustment` |
| `verify_overlay.py` | End-to-end three-curve isolation check for **any** `per_tile_overlay` code (`--code j --cycle 2026-09 --raw-cache-dir …`): (a) raw, (b) subtract-only, (c) subtract+add world 28d-MA curves from the cached raw pull, Dec-15 deltas, pass-through `(c−a)/(c−b)` against a 0.5–1.5× band, plot + numbers JSON in the spec dir's `plots/`, curves cached to parquet so re-plotting never re-forecasts. Replaced the per-code `verify_lol_overlay.py` / `verify_mozillaonline_overlay.py` (2026-09-04) |
| `build_adjustment_ladder.py` | **Build and cache the desktop adjustment ladder** for a cycle (`--cycle 2026-09 --forecast-start-date 2026-09-02 --raw-cache-dir … --config-from <build>.meta.json`): raw model + one run per overlay to measure each Dec-15 impact, then the cumulative subsets the impact order needs, each a real desktop forecast via `main(disabled_adjustments=…)` cached under `data-official/{cycle}/adjustment_ladder/<codes>.<key>/` where the key hashes seam + config + the fingerprints of only the overlays in that run (a spec edit re-runs only rungs containing that code). Display-layer codes (`h`) are exact and need no run. Writes `ladder_manifest.json`, which the canonical notebook's `[plot-desktop-ladder]` reads — the notebook never runs the model, so the chart refreshes only when this is re-run. `--dry-run` prints cached vs needed. **Prompts for confirmation before every model run** (`--yes` only with the user's explicit approval of that rebuild; a broad refresh is not approval). Logic in `mozaic_daily.ladder` |
| `build_adjustment_combinatorics.py` | **Run and cache every subset of a cycle's droppable desktop overlays** (same flags as the ladder: `--cycle --forecast-start-date --raw-cache-dir --config-from`, plus `--pin CODE` to hold an overlay on in every run, `--reuse-run LABEL=PATH` to adopt an existing parquet as a subset's run after a sidecar check (the canonical build as the all-in subset, a raw-interval build as `raw`), and `--mobile-run p=PATH --mobile-run raw=PATH` to record the mobile pair for the effects export). 2^N real desktop forecasts sharing the ladder's cache dir and content keys, so the raw run, singles and cumulative rungs are reused. Display-layer codes (`h`) are always on and exact. Writes `data-official/{cycle}/adjustment_combinatorics/combinatorics_manifest.json` with every run's `artifact_sha1`. `--dry-run` lists cached vs needed; **prompts before running** (`--yes` only with explicit approval). Logic in `mozaic_daily.combinatorics` |
| `render_adjustment_combinatorics.py` | Turn the combinatorics manifest into a self-contained `index.html` (`--cycle 2026-09`): one section per combination with the canonical desktop headline chart (actuals, prior delivered, this subset with `h`, 2025 calendar-aligned, targets, DRAFT watermark), a Dec-15 table against the prior cycle, the all-in build and the three targets, an all-combinations overview chart, and a CSV twin. Never runs the model; one BigQuery actuals query cached beside the report. **Cycle-scoped** (`CYCLE_SETTINGS`) |
| `export_adjustment_effects.py` | **Turn the combinatorics runs into the cycle's tracked adjustment-effects record** (`--cycle 2026-09 --desktop-canonical <parquet> --mobile-canonical <parquet>`): `adjustment_subsets.csv` (Dec-15 per subset, without/with display layer), `adjustment_effects.csv` (per code: nominal curve value, single / marginal / Shapley realized Dec-15, pass-through), `adjustment_curves_28ma.csv` (world 28d-MA per subset from the seam), `adjustment_dec15_by_country.csv`, `adjustment_effects.meta.json`. Display-layer values render from the live `adjustments/` specs. **Currency check** against the canonical sidecars (seam, config, overlay fingerprints, all-in / `p` run identity by `artifact_sha1`); `--check-current` exits 2 when stale and prints the rebuild command; a stale export needs `--allow-stale`. Never runs the model. Logic in `mozaic_daily.adjustment_effects` |
| `compare_adjustment_effects.py` | Join two cycles' `adjustment_effects.csv` (`--prior 2026-08 --current 2026-09 [--view shapley|single|marginal]`) and print per code the realized Dec-15 on each side, the delta, and its exact split into curve-moved vs pass-through-moved; codes on one side only are added / removed. Writes `adjustment_effects_vs_<prior>.csv` beside the current file |
| `score_near_horizon.py` | Score a build at the near-horizon trough and Dec-15, global and ex-CN/IR, pre/post headwind. Uses the canonical `display_ma`; its ramp clamps at the anchor date. **Scores are not comparable across the 2026-07-29 `Fix A` boundary** |
| `seam_bridge.py` | Seam kink diagnostic (`kink_score`) + daily-level bridge helpers; platform-agnostic |
| `compute_forecast_intervals.py` | **Prediction intervals for one build from its fitted `mozaic_objects.*.pkl`.** Rebuilds the 1,000 world-total sample paths, asserts their median reproduces the parquet's world forecast, and writes daily + 28d-MA bands (50/80/90 by default), a Dec-15 / trough summary, and plots. Bands are **quantiles of the trailing mean across paths** (actuals spliced in front), never the trailing mean of per-day quantiles; `point_forecast_28ma` (mean of the median path, the published convention) is written beside the band-centre `median` because they differ under skew. Prophet predictive intervals — not calibrated. Platform is read from the parquet name (`ld-D` → desktop world row `{"os": "ALL"}`, `gm-D` → mobile world row `{}`). Logic in `mozaic_daily.intervals`. Uses: `data-official/2026-08/desktop_raw_ci_2026-08-02/` (on `august-forecast`), `data-official/2026-09/{desktop,mobile}_raw_ci_2026-09-09/` |
| `run_param_scan.py` | **One desktop forecast with a fully configurable `DesktopModelConfig`.** The only way to reproduce a locked parameter config (currently **g01**) — `run_main.py` has no parameter flags. Injects via `main(model_configs=...)`; it no longer monkeypatches `process_data_source`. `--disable-adjustment CODE` (repeatable) suppresses any registry overlay and leaves it off the marker |
| `run_pinned_scan.py` | Desktop forecast with per-tile Prophet **changepoints pinned to April's locations** — built to test whether changepoint placement explained the April↔June trend gap |
| `run_desktop_gradient.py` | Drives desktop July-2026 parameter-search rounds (gradient + combinations); each probe is one `run_param_scan.py` invocation |
| `run_aug_trough_gradient.py` | Aug-2026 **near-horizon** finite-difference gradient, targeting the 28d-MA of world-headline `legacy_desktop` DAU (the `aug22-retune` search) |
| `run_s01_gradient.py` | Sensitivity gradient around the s01 centre point |
| `run_summer_trough_grid.py` | The summer-trough grid driver (`summer-trough-v2`) |
| `run_trend_only_grid.py` | Trend-only grid. **Refuses holiday overrides by design** — holiday knobs are excluded from tuning by policy |
| `run_mobile_param_scan.py` | One `glean_mobile` DAU forecast with a configurable `MobileModelConfig` — the mobile analog of `run_param_scan.py`. Exposes **all seven non-holiday knobs**; the three seasonality flags were added 2026-07-31 (before that, no mobile scan could vary them, which is why no mobile build has ever left `seasonality_regime='auto'`). `--no-organic-split` turns the paid treatment off and stamps the output `.raw.` (total-DAU mobile, no paid split) |
| `mobile_scoring.py` | Pure scorer for August `adj-p` mobile parquets. Scored KPI is the ALL-MOBILE world **Dec-15 28d-MA post-headwind**; seam step / slope kink / YoY are **reported, never scored**. Reads `mobile_dau` from the headwind spec and uses mobile's `"{}"` segment selector — both differ from `score_near_horizon.py`. **Cycle-scoped**: repoint `FORECAST_START`, `DEFAULT_HEADWIND` and `TARGET_DEC15` each roll-forward |
| `run_mobile_gradient.py` | August mobile round-1 central-difference gradient: center + 5 numeric axes × ±δ, first **and second** derivatives of Dec-15. Parallel, idempotent, slug-collision guarded. `--regime` re-runs the full set under a different `seasonality_regime`. Holiday knobs excluded by policy. Note the center is threaded explicitly into the pool workers — macOS spawns rather than forks, so a worker reading module-level `CENTER` would silently drop the regime override |
| `tile_corr_distribution.py` | Reports the per-tile level/volatility correlation behind desktop's `seasonality_regime="auto"` per-tile regime switch; used to place grid points |
| `mobile_app_breakdown.py` | Per-app DAU split (Fenix / Firefox iOS / Focus Android / Focus iOS) of a mobile build, point-in-time and trailing-window, for actuals and forecast. Cross-checks `ALL MOBILE` against the sum of its parts and the training rows against the raw pull. Defaults are **cycle-scoped** |
| `fetch_raw_pull.py` | Fetches and checkpoints **one** data source's raw BigQuery pull, with no forecasting. Exists to break a circular dependency at cycle roll-forward: `build_fenix_organic_split.py` needs the cycle's `mozaic_parts.raw.glean.mobile.DAU.parquet` for its shredder-drift check, but `run_mobile_param_scan.py` refuses to run until a paid spec is gated to the new date — and gating that spec needs the split. **The raw pull is model-config independent** (it is the query result, taken before any model or overlay), so the artifact is byte-identical to what a tuned scan would write, and the later scan consumes it via `--raw-cache-dir` with no re-query |
| `build_kpi_sheet_update.py` | **Fold a cycle into the KPI workbook's "Official Forecast Data" tab.** `--sheet-export` (the tab's CSV from Sheets) + `--cycle`; derives the seam from `csv/<month>_canonical_curves.csv`, the outgoing `CURRENT` cycle and its month label from the export; `--rename OLD=NEW` fixes mislabelled blocks; promotes by default or `--draft`s as `FUTURE *`; splices the outgoing forecast onto the prior line with the handoff blank; `--expect-dec15 product=INT` locks the headline. Writes `data-official/{cycle}/kpi_sheet/official_forecast_data.<publish>.csv` + `.meta.json` + `source_data/sheet_export.<publish>.csv` + `plots/kpi_sheet_<publish>.png`; `--dry-run` prints inventory and plan only. Refuses to overwrite; never uploads. Driven by `/update-kpi-sheet`; logic in `mozaic_daily.kpi_sheet` / `kpi_sheet_checks` |
| `pull_paid_dau_curve.py` | **Turn the marketing team's paid-DAU query into files.** Resolves the GMIO widget's `{{metric}}` / `{{country}}` templates (default Total Paid DAU / All), runs it read-only through `bq_query.py`, saves the template SQL, resolved SQL, JSON result and CSV **verbatim** under `data-official/{cycle}/marketing/source_data/`, enforces the strict four-column weekly contract, and writes the pull-date-suffixed daily paid-DAU level `p` consumes as delivered (parquet + csv twin + meta + workbook + plot; no lift, no anchor since 2026-09-09) plus `PENDING_WIRING.md`. Never overwrites an earlier pull; never touches `organic.json`, tests, or the registry — wiring is a separate step. `--from-json` rebuilds from a saved result without querying. `--from-xlsx` imports **one scenario column of a delivered workbook** instead (sheet + date/actual/forecast columns named, optional `--fill-actual-from 'sheet!col'` for a week blank in both, `--column-legend` for the producer's own words, `--variant` mandatory; workbook copied verbatim to `source_data/delivered.*.xlsx`). Driven by the `/pull-marketing-curve` skill; logic in `mozaic_daily.paid_curve` / `paid_curve_workbook` / `paid_curve_provenance` / `paid_curve_files` |
| `verify_training_rows_are_actuals.py` | Confirms a forecast parquet's `training` rows equal raw BigQuery actuals over sampled date windows. Run before using training rows as a stand-in for an actuals query (e.g. the canonical notebooks' prior-year reference line), which saves ~1 TB of scan per notebook run. **Exit 0 = safe to substitute** |
| `export_desktop_no_headwind_csv.py` | Writes the **desktop-only, `h`-removed** counterfactual twins of a cycle's canonical CSVs (`*.DESKTOP_ONLY.WIN10_HEADWIND_REMOVED.csv`) beside the published pair. Pure arithmetic on the **published CSVs** plus the current and prior `headwind.json` — possible because `h` is display-layer, so `published − ramp` is exact with no model re-run and no parquet access. Strips the prior-July column with **July's own frozen spec**; July's artifacts are read-only. Every value column carries a `_NO_WIN10_HEADWIND` suffix so the canonical schema `KeyError`s rather than silently reading the counterfactual, and the summary carries `win10_headwind_added_back_*` so the published figures re-derive by subtraction. Renders ramps through the package's `render_adjustment` (any display-layer type, incl. `daily_file`); strips **only** `headwind.json` and names any other desktop-moving spec on stdout as left in. Only `h` is removed — `l` and `o` are baked into the parquet. **Cycle-scoped**: repoint the constants at roll-forward |
| `export_desktop_ex_ir_cn_csv.py` | Writes the **desktop-only, ex-Iran/ex-China** twins of a cycle's canonical CSVs — **four files**, `h`-applied and `h`-removed (`*.DESKTOP_ONLY[.WIN10_HEADWIND_REMOVED].EX_IR_CN.csv`). Unlike `export_desktop_no_headwind_csv.py` this **reads the parquets**: the published CSVs hold only world totals, and subtracting per-country 28d MAs is invalid because `display_ma`'s splice is **non-linear** (~2,900 DAU inside the splice window), so the daily series is differenced first and `display_ma` recomputed. Exactness rests on `ALL == sum(country tiles)`, asserted with a documented float tolerance. `h` is applied at its **full, unscaled anchor** — the Win10 mechanism was measured ex-IR/CN to begin with, and `score_near_horizon.py`'s `ex_cn_ir` scope does the same. Actuals come from the parquet's `training` rows, so they end one day earlier than the published files. Reuses the ramp helper from `export_desktop_no_headwind_csv.py` rather than adding a seventh `linear_ramp` implementation. Load-bearing check: the **world** curve rebuilt from each parquet must reproduce the published CSV. **Cycle-scoped** |
| `export_desktop_daily_csv.py` | Writes the **desktop-only DAILY (unsmoothed)** twin of a cycle's canonical curves CSV (`*.DESKTOP_ONLY.DAILY.csv`), same layout as the published MA file, with `h` on it. `h` is defined on the 28-day MA and a trailing mean of a linear ramp lags it by 13.5 days, so the daily headwind is the ramp **advanced 13.5 days** (`0.5·(ramp(t+13)+ramp(t+14))`, exact for `linear_ramp`, refused for other types); `rolling(28).mean()` of the file then reproduces the published curve to the DAU from seam+27, asserted on write. Costs a seam-day step of 13.5 slopes (−131,500 for August 2026; July's spec ramps from April so its step is −570,843) and a Dec-15 daily headwind deeper than the anchor by the same amount. Prints a "weirdness ledger" of every such number; the csv/ README carries it. Reads the parquets via `load_forecast` with a per-cycle required state (`["i","j","l","o"]` for September, `["l","o"]` for the August prior); actuals are training rows so they end one day before the published file's. **Clamped specs** (`clamp_at_anchor`, September 2026 on): the advance is exact only on a straight piece, so `--post-anchor-rule exact|flat_at_anchor|advanced_clamped` picks the daily headwind after Dec-15 (`exact`, the default, re-smooths to the flat curve through Dec-31 at the cost of a 28-day sawtooth in the daily headwind); the verify window follows the rule. Also writes `plots/desktop_daily_export_vs_published_ma.png`. **Cycle-scoped** (September 2026) |

## Where new code goes

- **New operational task**: add a script here, not inside `src/mozaic_daily/`
- **Reusable logic**: if a script grows shared helper functions, extract them into `src/mozaic_daily/` (or a new module there) and import
- **Throwaway one-offs**: `tmp/` is for intermediate data and scratch files, not scripts. Scripts here are versioned and re-runnable

### 2027 Glean-history draft (branch `glean-2027-forecast`, `data-official/2027-glean-draft/`)

- `run_glean_history_forecast.py` — **The only entry point for the file-fed Glean-history desktop source** (`DataSource.GLEAN_HISTORY_DESKTOP`, OS × country tiles, DAU + the new `Metric.MAU`).

Claim 1 — The migration is a measurable, additive tailwind

The migrating build is its own app_name = "Firefox Desktop MozillaOnline" (NOT a distribution_id — distribution_id='MozillaOnline' is a tiny ~28K accounting tag). As users update they flip to app_name = "Firefox Desktop", the canonical series the forecast models — which historically excluded them. So the canonical total rises exactly as the MozillaOnline build drains, starting ~Jun 2.

Claim 2 — Conservation: canonical rise ≈ MozillaOnline drain

Two independent estimators of the same migration (all-country, 28d-MA): the canonical rise above baseline (operative — what we add to the forecast) and the source drain (cross-check). They track within ~21% over the window; the model (black dashed) is fit to the rise up to the red cutoff (recent partitions read low).

Measured (28d-MA, all-country) at 2026-06-24: canonical rise ≈ 595,356; source drain ≈ 470,054.

Claim 3 — Two cohorts, release ≫ ESR (matches Brad)

Splitting the source by update channel: release dominates and started Jun 2; ESR is small and started Jun 16 — the same structure as Brad's 494K / 68K.
